ROLE & PERMISSION MODULE

Role & Permission Guide

The Role & Permission module is used to define user roles, manage permissions, control access to menus and actions, and support secure segregation of duties in the Finance Management System.

Roles Create job-based roles such as Operational, Controller, Treasury, and Administrator.
Permissions Control which pages, data, and actions are available to each role.
Menu Access Show or hide specific application menus based on assigned permissions.
Segregation of Duties Separate transaction creation, review, approval, and payment release responsibilities.
01

Role Overview

A role is a collection of permissions assigned to users who perform similar responsibilities within the Finance Management System.

Why roles are important

  • They simplify access administration for users with similar responsibilities.
  • They control which modules and records users can access.
  • They limit sensitive actions, such as approving or releasing payments.
  • They support auditability and segregation of duties.
  • They reduce the risk of unauthorized changes to financial data.

Recommended role management flow

1
Define Role Create a role based on a job function or responsibility.
2
Configure Permissions Select accessible menus, actions, and data scopes.
3
Assign to Users Apply the role to the users who need that access.
4
Review Regularly Review access after job, department, or policy changes.
i

Role and permission administration should be limited to authorized system administrators. Incorrect permission settings can expose sensitive finance data or enable unauthorized transaction actions.

02

Role List

The Role List displays all roles configured in the system and provides access to review, edit, or manage each role’s permission settings.

Typical actions from the Role List

  • Search for a role by name or keyword.
  • Review the list of users assigned to a role.
  • Open role details and permission settings.
  • Create a new role.
  • Edit an existing role.
  • Deactivate a role when it is no longer needed, if supported.

How to find a role

  1. Open the Role menu.
  2. Use the search field to enter a role name.
  3. Use filters if the system supports role status or module filters.
  4. Select a role from the result list to view its details.

03

Create Role

Create a new role when a job function requires a unique combination of menu access, actions, approval authority, or data scope.

How to create a role

  1. Open the Role menu.
  2. Click Add Role, Create, or the equivalent action.
  3. Enter a clear and descriptive role name.
  4. Add a description that explains the business purpose of the role.
  5. Select the required permissions for menus, pages, and actions.
  6. Set the role status to active if the role is ready to be assigned.
  7. Click Save.

Recommended role naming examples

  • Operational Staff
  • Operational Approver
  • Controller Reviewer
  • Controller Approver
  • Treasury Processor
  • Treasury Approver
  • Master Data Administrator
  • System Administrator

04

Edit Role

Edit a role when permissions, menu access, approval authority, or business responsibilities need to be updated.

When to edit a role

  • A new finance module or feature is introduced.
  • Business workflow or approval requirements change.
  • A role has too much or too little access.
  • An existing permission needs to be corrected.
  • Organizational responsibilities have changed.

How to edit a role

  1. Open the Role menu.
  2. Find and select the role to update.
  3. Click Edit.
  4. Update the role name, description, permissions, or status as needed.
  5. Review all changes carefully before saving.
  6. Click Save Changes.
  7. Review users assigned to the role after changes are applied.

05

Assign Permissions

Permissions define the actions a role can perform in each module, such as viewing, creating, editing, approving, releasing, or exporting records.

Common permission types

View Allows users to open a menu, page, list, or record detail.
Create Allows users to create new records, transactions, or master data.
Update Allows users to edit existing records when the workflow permits changes.
Delete Allows users to delete records when deletion is permitted by system rules.
Approve Allows users to approve, return, or reject transactions in approval workflows.
Release Payment Allows authorized users to perform the final payment release action.
Export Allows users to download transaction, report, or master data records.
Manage Users Allows users to create, update, deactivate, or reset user accounts.
Manage Roles Allows users to configure roles and permission assignments.

How to assign permissions to a role

  1. Open the Role menu.
  2. Select the role you want to configure.
  3. Click Edit or open the role permission settings.
  4. Select the required permission categories.
  5. Enable only the menu and action permissions required by the role.
  6. Review sensitive permissions such as approval, payment release, user management, and role management.
  7. Click Save.

06

Menu Access

Menu access controls whether a role can see and open specific modules in the application navigation.

Finance Management System menu areas

Dashboard Access to summary cards, notifications, charts, and role-relevant information.
Operational Access to Purchase Orders, Cash Advances, Payroll, Allowances, Liquidation, and related approvals.
Controller Access to document review, invoice confirmation, verification, and controller approvals.
Treasury Access to Payment List, Payment Process, Approval, and Payment Release.
Transaction History Access to historical transaction records, audit trails, and activity logs.
Master Data Access to Vendors, Principals, Vessels, Entities, Banks, Currencies, Taxes, and other references.
User Management Access to user account creation, updates, password resets, and status changes.
Role Management Access to role creation, editing, and permission configuration.
i

A user may need both a menu-level permission and an action-level permission. For example, a user may view the Treasury menu but not have permission to release payments.

07

Assign Role to User

After a role is configured, assign it to the appropriate users through the User Management module.

How to assign a role to a user

  1. Open the User menu.
  2. Search for and select the target user account.
  3. Click Edit.
  4. Find the Role or Assigned Roles section.
  5. Select the required role.
  6. Assign any additional data scope, such as entity, department, vessel, or approval limit, if available.
  7. Save the user changes.
  8. Ask the user to sign out and sign in again if the system applies new permissions only after a new session starts.

Role Examples

The following examples illustrate how roles can be separated across the Finance Management System. Adjust permissions according to your organization’s policies and approval matrix.

Role Example Primary Access Typical Restrictions
Operational Staff Create and submit Purchase Orders, Cash Advances, Payroll, Allowances, and Liquidation records. Should not approve their own transactions or release payments.
Controller Reviewer Review documents, confirm invoices, validate transactions, and return incomplete requests. Should not create source transactions that they are responsible for reviewing.
Treasury Processor View payment requests and prepare payment instructions. Should not release payments unless specifically authorized.
Treasury Approver Approve payment instructions within the assigned approval authority. Should not approve payment requests that exceed their approval limit.
System Administrator Manage users, roles, permissions, and system-level configuration. Should not perform routine finance approval or payment release actions unless specifically authorized.
✓

Role and Permission Security Guidelines

Follow these controls to maintain secure role administration and reduce the risk of unauthorized financial actions.

1
Apply Least Privilege Grant only the access necessary for the user’s current responsibilities.
2
Separate Duties Separate transaction creation, review, approval, and payment release roles.
3
Review Periodically Review roles and permissions regularly, especially after organization changes.
4
Test Changes Verify new or changed roles using a test user before assigning them broadly.
!

Do not grant a single user unrestricted access to create, approve, and release the same payment unless this is explicitly authorized by company policy and supported by compensating controls.
