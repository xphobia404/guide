ROLE & PERMISSION MODULE

Role & Permission Guide

The Role & Permission module defines user roles, controls permissions and menu access, and supports secure segregation of duties in the Finance Management System.

RolesCreate job-based roles for operational and administration functions.
PermissionsControl accessible pages, records, and actions.
Menu AccessShow appropriate application menus for each role.
Segregation of DutiesSeparate transaction creation, approval, and payment responsibilities.
01

Role Overview

A role is a collection of permissions assigned to users with similar responsibilities.

Role Management Overview

Use the Role menu to view configured roles and manage access configuration.

Screenshot — Role Management overviewrole-overview.png

Recommended role management flow

1
Define RoleCreate a role based on job responsibilities.
2
Configure PermissionsSelect accessible menus and actions.
3
Assign to UsersApply the role to authorized users.
4
Review RegularlyReview access after policy or job changes.
i

Role administration should be restricted to authorized administrators because permission changes can affect sensitive finance access.

02

Role List

The Role List displays configured roles and provides access to review, edit, and maintain permissions.

Typical actions

  • Search for a role by name or keyword.
  • Review users assigned to a role.
  • Open role details and permission settings.
  • Create or edit an existing role.

How to find a role

  1. Open the Role menu.
  2. Use the search field to enter a role name.
  3. Select a role from the result list to view its details.
03

Create Role

Create a new role when a job function needs a unique combination of menus, actions, approval authority, or data scope.

How to create a role

  1. Open the Role menu and select the create-role action.
  2. Enter a clear role name and description.
  3. Select the required permissions.
  4. Review the settings and save the new role.

04

Edit Role

Edit a role when its name, description, permissions, menu access, or business responsibilities need updating.

How to edit a role

  1. Open the Role menu and find the target role.
  2. Open the available action menu and select Edit.
  3. Update role details or permissions as required.
  4. Review the effect on assigned users and save the changes.

05

Assign Permissions

Permissions define actions a role can perform, including viewing, creating, updating, approving, and releasing records.

ViewOpen a menu, page, or record detail.
CreateCreate transactions or master-data records.
UpdateEdit records when the workflow permits changes.
DeleteDelete records when allowed by system rules.
ApproveApprove, return, or reject transactions.
Release PaymentPerform the final payment release action.
ExportDownload reports or transaction records.
Manage UsersCreate, update, or reset user accounts.
Manage RolesConfigure roles and permission assignments.
!

Grant approval, payment release, user-management, and role-management permissions only with explicit authorization.

06

Menu access determines which modules a role can see and open in the application navigation.

Role ManagementRole creation, editing, and permission configuration.
07

Assign Role to User

Assign configured roles to users through the User Management module.

  1. Open the User menu.
  2. Find the target user account and select Edit.
  3. Find the Role or Assigned Roles field.
  4. Select the required role and save changes.
  5. Ask the user to sign in again if permissions are applied on a new session.
✓

Test the user’s access after assignment to confirm expected menus are available and restricted actions remain unavailable.

i

Role and Permission Security Guidelines

Apply these controls to maintain secure role administration.

1
Apply Least PrivilegeGrant only access necessary for current work.
2
Separate DutiesSeparate creation, review, approval, and payment release.
3
Review PeriodicallyReview access after organizational changes.
4
Test ChangesVerify new roles with a test user before broad assignment.
!

Do not give one user unrestricted ability to create, approve, and release the same payment unless explicitly authorized and controlled.
